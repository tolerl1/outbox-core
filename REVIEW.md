# Repository review — outbox-core

## Review 2 — `e8e4b95` (2026-07-15)

Full code, security, and performance pass over `src/`, the shipped schema, tests, and CI.
Baseline health: 26 unit + 34 integration tests pass (integration suite was run against a
real Postgres 16 for this review), `ruff check`, `ruff format --check`, and `pyright`
(strict) are all clean. All 12 findings from Review 1 are confirmed resolved on `main`.

Checked and found sound:

- **SQL injection**: the claim query's `.format(topic_clause=...)` only ever interpolates a
  fixed literal; topics are bound via an expanding `bindparam`, and every other statement is
  built with SQLAlchemy Core. No injectable path from user data to SQL text.
- **Concurrency core**: the single-round-trip `FOR UPDATE SKIP LOCKED` claim, lease-based
  reclaim with the at-claim `attempts` increment (poison-message guard), and the
  status+worker_id fencing on all three outcome writes are correct and covered by real
  concurrency tests.
- **Loop resilience**: `run_forever()` catches `Exception` (not `BaseException`), so DB blips
  are survived and task cancellation still propagates.
- **Schema/model drift**: the integration suite builds its schema from the shipped
  `0001_initial.sql`, so drift shows up as a test failure.
- **Packaging/licensing**: MIT license present in both `LICENSE` and `pyproject.toml`;
  `py.typed` ships; no secrets in the repo (CI credentials are throwaway service-container
  values).

Findings 13–15 were verified empirically against Postgres 16, not just by reading.

## Review 1 — `980d39e` (all findings resolved)

Reviewed at `980d39e` (2026-07-15). Baseline health: 22 unit tests pass, `ruff check`,
`ruff format --check`, and `pyright` (strict) are all clean. The findings below are
design/robustness gaps, not broken code.

The core design is sound: the single-round-trip `FOR UPDATE SKIP LOCKED` claim,
lease-based recovery, and the writer's "never own the transaction" rule are correct
and well-tested (including a real concurrency test). The issues concentrate in the
relay's failure-handling edges and in packaging.
